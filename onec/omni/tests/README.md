# Проверки расширения MAX

## Даты события (1.1.0.28)

`event-dates-regression.bsl` — чистые проверки четырех способов расчета, дробных
часов, границ года/високосного дня, ошибочных дат, скалярной копии контекста,
ошибок ручного BSL и восстановления безопасного режима. Записей/HTTP нет.

`event-dates-scheduler-regression.bsl` — реальный расчет кандидатов и запросы:
до/после/дата объекта, границы окна, идентичность строк после перестановки,
отметки доставки, перенос заявки, исключения и миграция старых этапов.
Запускается через `execute_code` только в изолированной базе; все фикстуры
откатываются, бот выключен, HTTP/отправка не вызываются.

`event-dates-context-regression.bsl` — сохраненная СКД с пользовательским алиасом
даты, выбор полей, неверный тип/отсутствующее поле, ручной алгоритм и событие
после окончания приема. Все записи откатываются, HTTP отсутствует.

## Проверка контактов MAX без пациента

`new-contacts-regression.ps1` формирует JSON-строку с BSL для `execute_code`
в **изолированной тестовой базе** с установленным расширением. Нужны существующие
бот и пациент. Вызовов MAX/VDS нет. Все тестовые записи откатываются транзакцией,
в том числе при ошибке. Используется запрос и свёртка из текущего модуля формы.

Проверяется:

- два одноимённых контакта без пациента остаются отдельными диалогами;
- два контакта одного пациента сворачиваются в один диалог;
- непрочитанные сообщения считаются раздельно;
- дата входящего обращения доступна для оповещений;
- состояния «В работе» и «Закрыт» независимы для разных контактов.

Ручная проверка формы после обновления:

1. Новый контакт виден по имени MAX во вкладках «Все» и «Новые».
2. Выбор контакта открывает только его переписку, не требует пациента.
3. «Создать / выбрать пациента» открывает общую «Форму поиска клиента».
   Подтверждённый номер из отправленного в MAX своего контакта подставляется
   в поля поиска и телефона. Выполнить поиск и выбрать существующего пациента
   либо создать нового штатной командой этой формы.
4. Выбранный или созданный пациент привязывается к исходному контакту MAX,
   чат обновляется; история сохраняется. Проверить также переключение на другой
   диалог при открытом поиске: привязаться должен исходный, а не текущий контакт.
   Закрытие поиска без выбора не меняет привязку. Чужая существующая привязка
   не перезаписывается. Если телефон ещё не отправлен или подпись не подтверждается
   (например, после смены токена бота), оператор вводит телефон вручную.
5. «Старт» создаёт входящее обращение; автоматическое приветствие не подавляет
   оповещение оператора о новом обращении.

Расширение сохраняет прежнее измерение регистра состояний «Пациент», добавляя
в его допустимые типы контакт MAX. Старые записи и ключи пациентов сохраняются;
для непривязанных контактов ключ интерфейса имеет префикс `contact:`.

`patient-selection-regression.ps1` формирует BSL для проверки версии 1.1.0.24:
подстановка подписанного собственного телефона, отказ от чужого контакта и
неверной подписи, привязка и повторный выбор того же пациента, изоляция контактов.
Создаёт тестового бота с фиктивным токеном, контакты и историю внутри откатываемой
транзакции; использует одного существующего пациента. Сетевых обращений нет.
Этот серверный тест не заменяет ручную проверку открытия штатной формы клиента.

`patient-search-parameters-regression.ps1` — статическая проверка версии 1.1.0.25:
при создании общей формы передаётся структура с параметром `Пациент` типа
`СправочникСсылка.Клиенты` (пустая ссылка для нового обращения). Это необходимо
для расширения клиента `бит_ФормаПоискаКлиента`, читающего `Параметры.Пациент`
в обработчике создания формы. Проверка не исполняет код клиентского расширения;
открытие формы, выбор и создание пациента проверяются отдельно в клиентской базе.

`calendar-patient-regression.ps1` — проверка версии 1.1.0.26. Формирует BSL для
`execute_code`: исполняется тело обработчика из исходника с подстановкой структуры
вместо формы, проверяется подключение события `Before`. Для записи и переноса из
чата сбрасывается признак клиента занятой ячейки; сторонние события и пустой клиент
его не меняют. Данные базы не записываются. Это не проверка реального интерфейса.

Ручная проверка календаря: выбрать существующую заявку пациента А, из чата пациента Б
нажать «Записать на приём», дождаться обновления и выбрать свободную ячейку.
Пациент Б должен остаться в поле «Клиент» и попасть в новую заявку. Повторить для
«Перенести», смены даты и обычной записи вне чата. Не сохранять тестовую заявку.
