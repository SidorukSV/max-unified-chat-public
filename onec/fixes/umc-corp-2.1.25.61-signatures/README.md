# Исправление подписей при отправке приема — 1.0.0.1

Отдельное исправительное расширение для **БИТ.Управление медицинским центром
КОРП 2.1.25.61**, режим совместимости 8.3.21. Не является обновлением расширения MAX.

## Ошибка и исправление

При отправке документа «Прием» по электронной почте штатный метод
`СформироватьПредставленияЭЦППоШаблонам` создает таблицу без `ЭтоПодписьМО`.
Для шаблона РЭМД с соответствующим ЭМД метод
`ПолучитьСтруктурыПодписейПоСтрокеШаблона` ищет по этой колонке и получает
«Неверное имя колонки» (РаботаСШаблонамиHTML, строка 2655).

Расширение заимствует только общий модуль `РаботаСШаблонамиHTML`.
Перехватчик дополняет отсутствующий признак по сообщениям РЭМД и вызывает
исходный метод со всеми исходными параметрами через `ПродолжитьВызов`.
Запрос повторяет правило штатной функции `бит_СертификатыЭЦП.ДанныеСообщенийРЭМДПоЭП`:
по UUID подписи выбирается максимальная ссылка непомеченного сообщения,
затем агрегируется признак подписи медицинской организации.

Таблицы с уже существующим признаком и другие типы коллекций не меняются.
Проверка `ПодписьВерна` остается штатной. Данные базы, документы и электронные
подписи не перезаписываются; права не расширяются, привилегированный режим
не включается. Новых регламентных заданий и сетевых вызовов нет.

## Установка

1. Сохранить резервную копию базы. Сначала проверить на копии рабочей базы
   с тем же набором расширений и под пользователем, у которого возникала ошибка.
2. Добавить `BUILD/ИсправлениеПодписейПриОтправкеПриема_1.0.0.1.cfe` как
   **новое отдельное расширение**. Не заменять им расширение MAX.
3. Убедиться, что расширение активно и применимо; перезапустить сеанс 1С.
4. Повторить подготовку отправки проблемного приема по электронной почте,
   проверить сформированный документ и отображение подписей.

Исправление предназначено для 2.1.25.61. Перед обновлением основной конфигурации
проверить необходимость исправления: в исследованных исходниках 2.1.25.79
штатный код уже создает и заполняет этот признак. Не оставлять исправление
активным на новом релизе без проверки. Откат — отключение/удаление только этого
расширения и перезапуск сеансов; миграция данных не нужна.

## Проверки 27.10.2026

- Исходная конфигурация извлечена из предоставленного дистрибутива 2.1.25.61.
  SHA256 CF: `F125FC079B1374B9ED1CC3885B0AACE839890A05EEDF4FCC4BE88002E5FF4524`.
- Структурная проверка CFE с исходниками основной конфигурации: 14 проверок, PASS.
- CFE загружен и применен в новой изолированной базе из этого CF.
- Платформа 8.3.27.2214, явная компиляция конечного CFE:
  `/CheckConfig -ThinClient -Server -ExternalConnection -Extension ИсправлениеПодписейПриОтправкеПриема`
  — код завершения 0, «Ошибок не обнаружено».
- BSL LS: 0 ошибок и 0 предупреждений. Информационное сообщение о восьми
  параметрах и подсказки о букве «ё» относятся к сохраненной штатной сигнатуре.
- Runtime через COM в изолированной 2.1.25.61: точная private-процедура
  расширения включена генератором в доверенную EPF; запрос выполняется на
  настоящем справочнике сообщений РЭМД. Воспроизведена исходная ошибка поиска
  отсутствующей колонки. После дополнения проверены подпись МО, подпись врача,
  недействительная подпись, удаленное сообщение, неизвестный UUID, сохранение
  уже заданного признака, пустая таблица и другая коллекция — PASS.
  Все созданные записи откатываются одной транзакцией; отправки не выполняются.
- Обратная выгрузка конечного CFE: модуль совпадает с исходником, версия 1.0.0.1.

Этот runtime проверяет процедуру дополнения и штатный отбор подписей,
а не весь интерфейс отправки приема. Клиентская база, набор сторонних расширений,
обычные роли и фактическая доставка письма здесь не проверялись.
Рабочая база не обновлялась. На клиентской платформе 8.3.27.1786 отдельного прогона не было.

Артефакт: 6477 байт.
SHA256 CFE: `F952C7DD9D4851243F8E68DCE90748523825850E78183F5EB314E1ED69D47CC7`.

## Повторение runtime-проверки

В отдельной базе 2.1.25.61 с отключенными заданиями создать доверенную EPF без
форм через `epf-init` и сгенерировать ее модуль:

```powershell
python tests/emit_regression.py <путь-к-модулю-EPF>/ObjectModule.bsl
```

Собрать EPF и вызвать `ВыполнитьРегрессию()` через внешнее соединение.
Тестовые экспортные методы в поставляемое расширение не включаются.
