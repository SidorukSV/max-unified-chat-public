# Исправления предрелизного ревью: 1.1.0.36

## Область выпуска

Расширение `бит_МедицинаМАКС` 1.1.0.36, backend 1.0.7. Исправления относительно
среза 1.1.0.35 (`7633b4478584750dd3dcad82185346606f7c9b57`).
Клиентская поставка: MAX-чат и рассылки, исходящий обмен 1С с VDS.
Миниприложение и публичный медицинский API этим выпуском не добавляются.

Рабочая база клиента и VDS в ходе исправлений не обновлялись. Проверки ведутся
только в разрешённой локальной «МАКС», БИТ:УМЦ 2.0.49.91, платформа 8.3.27.2214.
Перед обновлением сохранена полная файловая копия базы при эксклюзивном доступе.

## Что изменено

| Замечание ревью | Исправление |
| --- | --- |
| R1: напоминание после отмены | Callback отменяет ожидающие сообщения и меняет поколение подготовки в транзакции заявки. Завершённые попытки не переписываются. Перед отправкой проверяются состояние, пациент, дата и врач заявки. |
| R2, R9: ложный успех и чужая последняя отправка | Общий контракт `sent / not_sent / unknown`; результат возвращается для UUID своей попытки. HTTP 207 и прикладной отказ не считаются доставкой. История обычного сообщения фиксируется до HTTP и обновляется по тому же ключу. |
| R3: повтор после потери ACK | Устойчивый ключ исходного MAX-события, независимый inbox. Бизнес-изменения, исходящее намерение и отметка обработки фиксируются вместе. Повтор обработанного события не выполняет обработчик снова. |
| R4: устаревшее уведомление о создании | Ожидающий IMMEDIATE пересобирается из нового снимка, включая адресата. Старые ожидающие снимки .35 без версии события сначала проходят подготовку, а не отправляются вслепую. |
| R5: ошибка рассылки ломает запись | Подписки сохраняют снимок и намерение. СКД, алгоритмы, текст, кнопки и даты рассчитываются отдельным обработчиком после записи объекта. Ошибка подготовки сохраняется с ограничением попыток, а не откатывает уже записанную заявку. |
| R6: неверные кнопки исчезают | Единая серверная проверка структуры клавиатуры при записи шаблона и формировании сообщения. Ошибочная клавиатура не превращается в пустую успешную. |
| R7: усечение настроек | Строковый ресурс расширен до 254 символов, согласованы ограничения; добавлены проверки типа, длины и чтения после записи. Ранее усечённые данные автоматически не восстанавливаются. |
| R8: фиксированная рассылка без СКД | Отсутствующий контекст допускает фиксированное сообщение; явный пустой результат СКД продолжает означать отбор без полученного события. |
| R10: дубли настроек | Исправлена проверка результата поиска: индекс не используется как булево значение. |

Дополнительно:

- Запрещён HTTP для обмена с VDS и MAX API; используется HTTPS без отключения проверки сертификата.
- Все обработчики старого HTTP-сервиса расширения возвращают 410 без чтения входных данных и исполнения старых операций.
- У обычной роли напоминаний убрана прямая запись служебных очередей.
- Идентичность контакта, пациент и отделение защищены обработчиком объекта, включая программную запись с `ОбменДанными.Загрузка`. Привязка выполняется проверенными серверными командами.
- Первое создание контакта сериализовано по боту и MAX ID. Найденные старые дубли требуют разбора администратора, произвольный контакт не выбирается.
- Повторяющиеся ошибки входящего события переходят в карантин после пяти попыток. Неизвестный исход отправки не запускает слепой повтор.
- Поля шаблона вычисляются один раз на сообщение и совместно используются текстом и кнопками. Старый renderer делегирует общему.

## Эксплуатация после обновления

Обновить расширение штатной заменой, не удалять его вместе с данными. После обновления
завершить старые сеансы. Сохранить существующие роли основной конфигурации;
всем сотрудникам нужна базовая роль МАКС, операторам — отдельная роль и отделение.
Новые технические регистры не требуют выдачи широких прав обычным пользователям.
См. [BASE-ROLE.md](BASE-ROLE.md).

Используются существующие задания обмена и обработки рассылок. Не создавать параллельные
дубликаты заданий. На тестовой копии не разблокировать все задания ради одного MAX-обмена.

Новые технические данные:

- `бит_ПодготовкаРассылокMAX` — снимок объекта, версия, попытки и ошибка подготовки;
- `бит_омни_ВходящиеСобытияMAX` — ключ исходного события, обработка и карантин;
- `бит_омни_ИсходящиеНамеренияMAX` — устойчивый UUID исходящего действия и результат;
- `бит_омни_ИдентичностиКонтактовMAX` — сериализация создания контакта.

Повтор подготовки после исправления алгоритма: под полными правами серверный вызов
`бит_ПодготовкаУведомленийMAX.ПовторитьПодготовку(Источник, Рассылка, Бот)` для конкретной
строки в состоянии «Ошибка». `Источник` — сохранённое имя метаданных и UUID,
а не произвольный BSL. Затем штатный обработчик подготовки.

Повтор карантина: `бит_омни_НадежныйОбменMAX.ПовторитьКарантин(Бот, Ключ, Причина)`
для конкретного SHA256-ключа, с полными правами, после устранения причины.
Вызов обрабатывает сохранённое входящее событие, не выполняя сетевую отправку внутри
его транзакции. Исходящее намерение забирает штатное задание.
Это служебные API, отдельная интерактивная форма разбора карантина не добавлена.

Не сбрасывать строки «Неопределено» и не очищать историю ради повторной отправки:
сначала сверить реальную доставку и UUID. Неизвестный исход означает в том числе
потерянный ответ после фактической отправки. Обычная ручная отправка оператора
не повторяется автоматически. Автоматические сообщения с достоверным `not_sent`
имеют ограниченный повтор; после исчерпания попыток требуется разбор.

## Границы и оставшийся технический долг

- Реальная доставка MAX/VDS, клики по всем формам и фактические профили клиентской КОРП требуют отдельной приёмки на клиентском тестовом контуре. Этот выпуск не является пентестом.
- Inbox обеспечивает однократность зафиксированной локальной обработки, но не обещает exactly-once доставки сторонним провайдером. При `unknown` приоритет — не отправить дубликат.
- Произвольный административный BSL с внешними файловыми/сетевыми побочными эффектами не становится транзакционным автоматически. Алгоритмы шаблонов должны вычислять значения без таких эффектов и не оставлять открытых транзакций.
- Большие формы и совместимые внутренние legacy-модули не переписаны целиком. Ненужный внешний HTTP-доступ закрыт, метаданные оставлены для безопасного обновления существующего расширения.
- Завершённые ключи очереди пока сохраняются и читаются в группе как защита от повторной отправки. Политика архивирования/сроков хранения и нагрузочная оптимизация требуют отдельного решения; удаление истории без него не выполнялось.
- Автоматическое восстановление ранее усечённых настроек и слияние старых дубликатов контактов не выполняются. Их значения проверяет администратор.
