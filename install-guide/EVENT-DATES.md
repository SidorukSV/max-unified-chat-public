# Даты события: расширение 1.1.0.28

В карточке рассылки добавлена настоящая табличная часть `ДатыСобытия`.
Для MAX она управляет отправкой в режиме **По расписанию**. Одна строка —
одно событие для одного шаблона сообщения этой рассылки. Для разных текстов
создайте разные рассылки. Обычное расписание других каналов не ограничивает
события MAX; режим **При записи объекта** остается немедленным.

## Настройка

1. Установите [расширение 1.1.0.28](../onec/omni/BUILD/бит_МедицинаМАКС_2026_09_09.cfe) вместо существующего `бит_МедицинаМАКС`
   и перезапустите сеансы. Backend 1.0.6 менять не требуется.
2. В карточке рассылки выберите шаблон сообщения и режим **По расписанию**.
3. В таблице **Даты события — MAX** добавьте строки и включите флаг **Вкл.**:

   | Шаблон расчета | Реквизит контекста | Часов | Результат |
   |---|---|---:|---|
   | За N часов до даты | ДатаНачала | 24 | За сутки до начала приема |
   | За N часов до даты | ДатаНачала | 2 | За два часа до начала приема |
   | Через N часов после даты | ДатаОкончания | 1 | Через час после окончания |
   | Дата объекта | Дата | — | Дата и время документа без смещения |

   «Дата объекта» использует выбранный реквизит, а не обязательно стандартную
   `Дата`. Смещение в этом режиме игнорируется. Допустимы дробные часы
   (например, 0,5 — 30 минут), от 0 до 87600.
4. Сохраните рассылку и включите ее для нужного MAX-бота в активных рассылках.
   Сохранение карточки само по себе рассылку не активирует.
5. Запускайте обмен MAX с интервалом не более минуты. В копии базы с глобальной
   блокировкой регзаданий используйте только ручной запуск, не снимайте блокировку.

## Источник контекста и область применения

Текущий обработчик MAX работает с документом **Заявка**, не с произвольным
справочником или документом. Без СКД доступны дата документа и реквизиты заявки;
список выбора показывает реквизиты типа `Дата` текущей конфигурации.

Если заполнена настройка **Контекст**, используется результат этой СКД:
таблица должна содержать `Заявка` (или `Ссылка`) типа `ДокументСсылка.Заявка`
и нужные поля дат. Имена дат выбираются из полей схемы либо вводятся вручную
как простое имя без выражений и вложенных путей. Дополнительные поля СКД
добавляются в контекст шаблона; дата должна оставаться типом `Дата`, а не
форматированной строкой. Параметр `Момент`, если определен в схеме, получает
текущее время расчета. Схемы «ПередЗаписью/ПриЗаписи» без самостоятельного
источника заявок не подходят для периодической проверки.

Получатель определяется по пациенту каждой заявки и его действующему контакту
этого MAX-бота. Настройка **Получатели** старой рассылки не используется этим
обработчиком: для отбора заявок настройте СКД контекста. Отмененные, удаленные,
групповые заявки, удаленные пациенты и заблокированные/непривязанные контакты
исключаются. Для событий после визита не требуется состояние «до прихода».
Кнопки подтверждения/отмены предназначены для будущего приема; в сообщениях
после визита используйте подходящий шаблон без этих кнопок.

## Ручной алгоритм

Выберите **Ручной алгоритм** и заполните колонку BSL. Код присваивает переменной
`Результат` дату отправки либо `Неопределено`, если событие нужно пропустить:

```bsl
Результат = Контекст.ДатаОкончания + 1.5 * 3600;
```

Код получает копию скалярных полей контекста (даты, строки, числа, булевы),
без ссылок, объектов и вложенных коллекций. Неверный тип/пустая дата и ошибки
алгоритма не приводят к отправке; сведения об ошибке записываются в журнал.

Создание, изменение и удаление ручного алгоритма разрешены только пользователю
с правом **Администрирование**, в том числе при программной записи объекта.
Модуль расчета недоступен для прямого клиентского серверного вызова.
Код хранится отдельно от данных: текст пациента не вставляется в исполняемую
строку. Выполнение идет в безопасном режиме платформы без включения
привилегированного режима.

**Это доверенный административный BSL, не песочница.** Глобальный контекст 1С
и права пользователя фонового задания остаются доступны. Ограничения времени
исполнения нет: ошибочный бесконечный цикл способен задержать обмен. Не пишите
здесь изменения данных, сеть или длительные операции. Алгоритм должен быть
детерминированным и вычислять дату из контекста, а не возвращать «сейчас» при
каждом запуске. Для произвольного алгоритма без СКД проверяются все неотмененные
заявки; на большой базе задайте узкий отбор СКД.

## Доставка и совместимость

Окно отправки: от рассчитанного времени включительно до 15 минут после него
не включительно. Пропущенные окна не догоняются. За проход обрабатываются
до 100 подходящих кандидатов каждой строки. Используется время сеанса 1С;
часовой пояс задания должен совпадать с журналом записи.

У строки есть устойчивый скрытый UUID. Перестановка строк его не меняет,
копирование создает новое событие. Ключ доставки учитывает рассылку, UUID строки,
рассчитанную дату и актуальное начало заявки; перенос или изменение даты может
создать новое событие. Перед отправкой контекст и настройки проверяются повторно.
При неопределенном результате HTTP автоматического повтора нет — требуется
сверка истории MAX.

Старые стандартные рассылки с пустой таблицей продолжают работать за 24 и 2 часа.
Команда карточки бота **Создать и включить напоминания за сутки и 2 часа**
добавляет стандартную строку, только если таблица пуста. Существующие строки
не переписываются. Для мигрированной строки сохраняется старый ключ доставки,
поэтому добавление второй строки не заставляет повторно отправлять первую.
Не удаляйте все строки стандартной рассылки для отключения: это возвращает
старый режим. Снимите **Вкл.** у строк либо отключите активную рассылку.

Диагностика: журнал `МАКС.ДатыСобытия.*`, `МАКС.Напоминания.*` и регистр
`бит_омни_ДоставкаНапоминанийMAX`. Расширена длина измерения `Этап` до 150;
существующие записи доставки сохраняются. Перед обновлением сделайте резервную
копию базы. Обновление не включает рассылки автоматически.

## Проверка выпуска

Проверено на локальной изолированной УМЦ 2.0.49.91, платформа 8.3.27.2214:
сборка с `/CheckConfig`, загрузка CFE и обновление структуры, создание формы
на клиенте (таблица, четыре шаблона, список дат), три регрессионных сценария
`event-dates-*`, совместимость старого отбора и активации стандартных напоминаний.
Отдельно проверены алиасы `appointment_date` и `appointment_time` типа Дата.
Тестовые записи откатывались; реальные MAX/VDS-вызовы не выполнялись.

Проверки XML формы и измененных метаданных прошли. Статический анализ нового
расчета и обработчика не обнаружил ошибок; в старой части модуля формы остается
диагностика использования `ТекущаяДата()` при настройке прежнего расписания.
Она не относится к расчету событий MAX, который использует время сеанса.
Клиентская конфигурация 2.1 и сквозная доставка настоящему боту этим выпуском
автоматически не обновлялись и не проверялись.
