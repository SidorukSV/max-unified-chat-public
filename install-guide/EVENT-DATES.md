# Событийная очередь — расширение 1.1.0.36

## Два режима

**При записи объекта:** в транзакции записи сохраняется снимок и намерение
подготовки в `бит_ПодготовкаРассылокMAX`. Отдельный обработчик выполняет СКД,
алгоритмы, расчёт текста, кнопок и дат, затем сохраняет готовые JSON сообщения
и адресата в `бит_омни_ОчередьСообщенийMAX`. Документ очереди не нужен.
HTTP при записи нет; откат объекта откатывает намерение. До завершения новой
подготовки старый снимок этого события не отправляется.

**По расписанию:** обычная периодическая рассылка, например ежедневно в 10:00.
При наступлении периода выполняются СКД, готовые сообщения и отметка запуска
фиксируются одной транзакцией. Блокировка пары бот/рассылка защищает от
параллельной подготовки. Таблица дат событий здесь не применяется.

Для обоих режимов MAX контекст СКД — 0/1 строка; больше одной — ошибка настройки.
Получатели — таблица с колонкой `Получатель`. Ноль строк заданной СКД контекста —
не отправлять. В периодическом режиме отсутствие СКД контекста допускается
для фиксированного сообщения.
Пациент без доступного контакта MAX пропускается без ошибки записи на прием.
Ошибка шаблона/расчёта даты сохраняется в намерении подготовки и не отменяет
уже записанный объект. После пяти попыток — состояние «Ошибка» и ручной разбор.
Служебные записи с `Загрузка` или `бит_омни_НеПроверять` новых намерений не создают.
Callback отмены отдельно снимает ожидающие напоминания в своей транзакции.

## Даты события при записи

Укажите принадлежность к объекту, событийные СКД, шаблон и строки таблицы:

| Шаблон | Реквизит контекста | Часов | Результат |
|---|---|---:|---|
| За N часов до даты | ДатаНачала | 24 | За сутки |
| За N часов до даты | ДатаНачала | 2 | За два часа |
| Через N часов после даты | ДатаОкончания | 1 | Через час |
| Дата объекта | Дата | — | Выбранная дата без смещения |

Поле должно присутствовать в результате СКД с типом `Дата`, не строка.
Список выбора берется из полей выбранной схемы; алиас можно ввести вручную.
«Дата объекта» использует выбранное поле, не обязательно стандартную `Дата`.
Дробные часы разрешены, диапазон 0–87600.

- Пустая таблица: немедленное событие, тоже через очередь.
- Все строки выключены: новых событий нет, это не немедленная отправка.
- Результат алгоритма `Неопределено`: строка пропускается.
- Впервые вычисленная дата уже прошла: сообщение задним числом не создается.
- Уже созданная просроченная очередь остается к отправке.

## Повтор, перенос и отмена

Ключ: объект + рассылка + бот + контакт + UUID строки + вычисленная дата.
У немедленного события вместо текущего времени постоянный маркер.
Текст не входит в ключ: повторная запись обновляет только ожидающий снимок.
Отправленные, ошибочные и сообщения с неизвестным результатом заново не создаются.

Немедленная рассылка дает одно событие на объект/рассылку/контакт. Для другого
бизнес-события настройте отдельную рассылку с соответствующим условием.

При переносе даты, смене получателя, удалении/выключении строки либо ложном
условии контекста старые ожидающие **отложенные** сообщения отменяются при
следующей записи объекта. Стандартные СКД исключают отмененную/удаленную
заявку и пустого пациента; пользовательские условия отмены задаются их СКД.
Стандартное немедленное уведомление о создании актуализируется и на повторной
записи, пока оно ожидает отправки: восстанавливается техническое условие
первоначального создания, остальные данные пересчитываются. Отмена или пометка
удаления снимает ожидающее уведомление. Отправленное заново не создаётся.

Уже захваченный снимок не переписывается: изменение объекта после захвата не
может отозвать начавшийся HTTP. Изменение настроек рассылки само по себе не
пересчитывает очередь — нужна запись исходного объекта.
Перестановка строк дат сохраняет их UUID; копирование создает новое событие.

## Отдельный отправитель

Задание **МАКС: отправка очереди сообщений** (`бит_омни_ОтправкаОчередиMAX`)
вызывает `бит_омни_ОчередьСообщенийMAX.ВыполнитьОтправку()`.
Оно независимо от входящего long polling: готовит событийные и периодические рассылки,
затем берет до 100 наступивших сообщений. Время — время сеанса 1С;
часовой пояс должен совпадать с журналом записи.

| Состояние | Значение |
|---|---|
| Ожидает | Готовый снимок до наступления срока |
| ВРаботе | Одна попытка захватила сообщение до HTTP |
| Отправлено | MAX подтвердил непустым MID |
| Ошибка | Предварительная проверка либо явный отказ |
| Неопределено | Таймаут, неоднозначный ответ или сбой процесса |
| Отменено | Ожидающее событие перестало соответствовать объекту |

Захват фиксируется отдельной транзакцией под блокировкой, HTTP — вне транзакции.
Параллельное задание не получает то же сообщение. Через 5 минут истекший захват
становится неопределенным, а не новой попыткой. Поздний ответ принимается только
для действительного UUID попытки.

**В регистре очереди рассылок автоматических повторов HTTP нет**, включая ошибки и HTTP429.
Это компромисс в пользу отсутствия дублей, не гарантия exactly-once.
Ошибочные и неопределенные записи требуют сверки журнала и истории MAX.
Не удаляйте их и не меняйте на «Ожидает» ради слепого повтора.
Пользовательской команды повторной отправки пока нет.

Отправитель не перерендеривает текст и не ищет нового пациента.
Он проверяет доступность бота/контакта, неизменность MAX-адреса и пациента,
актуальность сохранённой версии заявки и отсутствие незавершённой подготовки.
Выключение бота/активной рассылки приостанавливает ожидающие сообщения.
Просроченная очередь обрабатывается без прежнего 15-минутного окна:
после долгого простоя сначала проверьте ее, текст мог устареть.

Очередь доступна для просмотра в подсистеме **МАКС**.
JSON не содержит токенов, но содержит переписку: ограничьте доступ и резервные
копии. Не очищайте терминальные строки без отдельной политики хранения ключей
дедупликации. Журнал: `МАКС.Очередь.*`.

## Ручной алгоритм

Код присваивает `Результат` дату либо `Неопределено`, например
`Результат = Контекст.ДатаОкончания + 1.5 * 3600;`.
Получает копию скалярных полей без ссылок и объектов. Изменение алгоритмов
разрешено только администратору, в том числе программной записью.
Модуль недоступен прямому клиентскому вызову. Текст пациента не встраивается
в исполняемый BSL; используется безопасный режим платформы.

Это доверенный административный код, **не песочница**. Глобальный контекст и
права пользователя задания подготовки доступны, ограничения времени исполнения нет.
Только детерминированный расчет: без записи данных, сети, длинных циклов и
возврата «сейчас» при каждом сохранении.

## Обновление

1. Сделайте резервную копию базы и сохраните прежний CFE.
2. Обновите backend до 1.0.7 и загрузите CFE 1.1.0.36
   в существующее расширение `бит_МедицинаМАКС`, обновите структуру,
   перезапустите сеансы. Протокол: [ACCEPTANCE-1.1.0.36.md](ACCEPTANCE-1.1.0.36.md).
3. Старые стандартные напоминания переведите явной командой карточки бота
   **Создать и включить напоминания за сутки и 2 часа**. Команда устанавливает
   событийные СКД и режим; пользовательские строки дат сохраняет.
   Она активирует рассылки — проверьте условия и тексты перед отправкой.
4. В рабочей базе настройте новое задание очереди, например каждые 60 секунд,
   назначьте пользователя с правами на очередь/данные и включите его.
   Предопределенное задание поставляется **выключенным**, без повторов при сбое.
5. В копии с общей блокировкой регзаданий запускайте именно новое задание
   вручную. Не снимайте общую блокировку ради MAX. Входящий обмен сам по себе
   очередь рассылок не отправляет. У входящего обмена теперь есть отдельный
   outbox для ответов на события и обычных сообщений; это не периодические рассылки.

Установка не активирует рассылки и не создаёт уведомления для всех старых заявок.
Обработчик лениво пересобирает уже существующие ожидающие снимки .35 без версии
события из текущей заявки. Для первой постановки уведомления по существующей
заявке нужна её обычная запись и соответствие настроенным условиям.
Старый регистр `бит_омни_ДоставкаНапоминанийMAX` сохранен для истории,
старый сканер удален. Произвольные рассылки 1.1.0.28 с датами в режиме
«По расписанию» вручную переведите в «При записи объекта» и настройте
событийные СКД/принадлежность.

Проверки: [README тестов](../onec/omni/tests/README.md).
Сквозная доставка клиентскому боту и штатная форма записи проверяются отдельно.
База клиента и VDS автоматически этим выпуском не обновляются.
