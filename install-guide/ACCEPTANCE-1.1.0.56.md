# Medina 1.1.0.56 — сохранять выбранного пациента после выбора отделения

Обработчик выбора отделения безусловно запрашивал пациента, если по подтвержденному
телефону найдена хотя бы одна карточка. Поэтому после успешного выбора пациента
следующий выбор отделения снова показывал список тех же карточек.

Теперь после закрепления отделения под блокировкой читается текущий пациент.
Если эта карточка входит в актуальный список по подписанному собственному телефону,
повторный запрос не отправляется. Для пустого выбора, другой карточки или карточки
с пометкой удаления меню остается. Автоматической смены пациента нет.
Исправление двойного подтверждения отделения из 1.1.0.55 сохранено.

## Проверки

- Реальный серверный dispatcher в изолированной копии 1С: регрессионный тест
  воспроизвел повторный запрос на 1.1.0.55 после выбора первой из двух карточек.
- Тот же тест на 1.1.0.56 прошел шесть вариантов: пациент не выбран, выбран первый
  или второй из двух, чужая карточка, пометка удаления, одна доступная выбранная
  карточка. В допустимых случаях меню не повторяется; в остальных оно появляется.
  Выбор отделения не меняет пациента. Проверены реальные patient/department callback,
  поиск карточек по телефону и очередь исходящих.
- Все тестовые карточки, контакты, телефоны, бот, отделение и очереди откатились
  одной транзакцией. HTTP и реальные отправки не выполнялись.
- 110 исходниковых unittest — PASS.
- Структура CFE: 0 ошибок, 3 прежних предупреждения; сборка с CheckConfig — PASS.
- Частичная загрузка версии/модуля с UpdateDBCfg — PASS, платформа 8.3.27.2214.
- Обратная выгрузка готового CFE подтверждает версию 1.1.0.56 и точное совпадение
  измененного производственного модуля с проверенными исходниками.

Рабочая база и VDS не обновлялись; карточка реального пользователя не изменялась.
Заменить существующее расширение и перезапустить выполняющие MAX сеансы.
Существующие сообщения с меню не удаляются. Правила обновления и ограничения
