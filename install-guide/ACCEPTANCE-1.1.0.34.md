# Проверки версии 1.1.0.34

## Подтверждено 12.09.2026

- 40 исходниковых контрактных тестов 1С проходят. Это проверки исходного текста, не выполнение всех ветвей в платформе.
- Backend: 28 тестов проходят, 1 тест с реальным Redis пропущен; реальной отправки в MAX в этом прогоне нет.
- Проверка структуры CFE: 0 ошибок, 4 предупреждения. Проверка формы чата: 15 проверок, без ошибок.
- Сборка CFE и `/CheckConfig` платформы 8.3.27.2214 в временной базе — без ошибок.
- Применимость CFE к локальной тестовой БИТ:Управление медицинским центром 2.0.49.91 — без проблем;
  версия 1.1.0.34 установлена после полной файловой резервной копии при эксклюзивном открытии файла базы.
- Созданы три шаблона: выбор отделения, подтверждение отмены, отказ от вложений.
  Повторная загрузка сохраняет пользовательский текст выбора отделения; рендерер использует этот текст.
  Тестовая правка текста откатилась. Очередь отправки не изменилась.
- В платформе прошёл JSON → таблица → JSON для кнопки переноса.
  Подтверждено добавление CR/LF функцией `Base64Строка`; транспорт удаляет их перед загрузкой файла.
- Через доверенную тестовую EPF прошли чистые проверки callback-парсера, nonce и JSON.
- Под локальным тестовым пользователем только с ролями «Администратор регистратуры» и «МАКС: базовые права»:
  полные права отсутствуют, привилегированный режим выключен, служебные настройки рассылок читаются,
  три параметра сеанса инициализированы, запись существующей карточки клиента проходит и откатывается.
  Чтение ботов, контактов и истории этому пользователю запрещено, как и предусмотрено.
- BSL lint интеграции и фасада отделений: 0 ошибок. В модуле настроек остаются 9 прежних замечаний анализатора
  к организации транзакций, в форме чата — прежний обоснованный `GetFormMethod` штатного поиска пациента;
  это не новые ошибки синтаксиса, проверка платформы проходит.

## Не считать завершённой приёмкой

Рабочая база клиента и VDS этой проверкой не обновляются. Пока не подтверждены сквозная доставка в настоящий MAX,
выбор файла через интерфейс тонкого клиента, пользовательские алгоритмы шаблонов и роли именно клиентской КОРП.
В локальном тесте регистратора нет активных рассылок, поэтому он не заменяет проверку записи заявки с активной рассылкой.

Изменение заявки через COM остановилось в типовом модуле `Битрикс` на `Тип не определен (HTTPСервисОтвет)`.
Это ограничение внешнего соединения; успешное выполнение ветвей подтверждения/отмены/переноса не доказано.
Временные настройки и данные откатились. Подготовлена отдельная доверенная EPF для штатного клиентского/серверного
контекста, с тестами состояния и булева свойства и обязательным откатом. Она не запускалась автоматически.

Проверка двух операторов также не завершена: COM отказал в создании фикстуры контакта (`DISP_E_MEMBERNOTFOUND`).
Причина этого отказа не установлена. Все временные отделения/боты откатились; контрольные запросы подтвердили
ноль собственных тестовых отделений, ботов, контактов, пользователей и профилей. Это не успешный тест RLS.

Computer Use недоступен (`native pipe unavailable`, os error 2); повтор и сброс соединения не помогли.
Типовые модули, общие настройки безопасности и рабочая база ради обхода этих блокеров не менялись.
