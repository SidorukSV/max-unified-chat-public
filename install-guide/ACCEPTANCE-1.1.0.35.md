# Проверки версии 1.1.0.35

## Результат 12.09.2026

Версия установлена только в разрешённую локальную тестовую базу «МАКС»:
БИТ:Управление медицинским центром 2.0.49.91, платформа 8.3.27.2214.
Перед обновлением создана полная файловая копия базы при эксклюзивном открытии файла.
Рабочая база клиента и VDS не обновлялись; реальных сообщений MAX не отправляли.

### Исправление относительно 1.1.0.34

В настоящем клиентском/серверном контексте обнаружен дефект сохранения настройки
`ПризнакПереносаЗаявкиMAX`: составной тип ресурса «Значение» регистра настроек
не включал ссылку на дополнительное свойство. Выбор состояния работал, выбор
булева свойства приводил к ошибке «недопустимый тип значения константы».

Заимствован ПВХ `СвойстваОбъектов`, его ссылочный тип добавлен в ресурс.
Общие функции хранения настроек, медицинские права и бизнес-логика callback не менялись.
Добавлен регрессионный тест соответствия типов настройки и её хранилища.
Ошибочно сохранённое ранее значение восстановить автоматически нельзя:
если такая настройка уже вводилась на .34, после обновления выбрать свойство заново.

### Проверки действий записи

Фиксированная доверенная EPF выполнена в тонком клиенте под «Управляющий»,
с отдельным серверным вызовом. Для этого клиента отключён автоматический запуск
регламентных заданий параметром `/AllowExecuteScheduledJobs -Off`.
Общие настройки базы, расписания заданий и защита опасных действий не изменялись.
Этот параметр не блокирует синхронные обработчики запуска и задания других сеансов.

Два независимых прогона — отметка состоянием и отметка булевым допсвойством — прошли:

- подтверждение записи и системная отбивка;
- запрос переноса, отметка заявки и состояние диалога без изменения времени приёма;
- отмена только после дополнительного подтверждения «Да»;
- «Нет» возвращает напоминание и не отменяет запись;
- повторные нажатия не дублируют изменения и отбивки;
- устаревший ключ подтверждения отмены отклоняется;
- чужой пользователь, пациент, неподходящий бот/контакт и устаревшая версия записи отклоняются.

Результат обработки: `ACCEPTANCE_OK_ROLLBACK_ONLY`.
Каждый прогон завершён откатом тестовых данных и настроек.
Использован фиктивный бот без токена, HTTP и реальная доставка не выполнялись.
Закрыт только собственный проверенный процесс тестового клиента.
Это выполнение серверных действий, не проверка кликов по всем элементам формы.

### Проверка отделений

На .34 успешно выполнены реальные запросы из четырёх отдельных COM-сеансов;
после установки .35 вся проверка повторена с тем же успешным результатом:

| Пользователь | Контакты / история / состояния | Прямой запрос чужого контакта |
| --- | --- | --- |
| Оператор отделения А | 1 / 1 / 1 | Отказ в доступе |
| Оператор отделения Б | 1 / 1 / 1 | Отказ в доступе |
| Оператор без отделения | 0 / 0 / 0 | Отказ в доступе |
| Полные права | 3 / 3 / 3 | Отдельно не проверялся |

В каждом сеансе привилегированный режим выключен. Только последняя учётная запись
имеет Полные права; остальные — штатную роль регистратора, базовую роль МАКС
и роль оператора отделения. Существующие пользователи и их права не менялись.
Временные пользователи, профили, отделения, бот, контакты и записи удалены адресно,
остатки собственных тестовых объектов — 0; очередь отправки не изменилась.

Прежний COM-сбой был ошибкой стендового скрипта: журнал ошибочно указывал создание
контакта, хотя не удавалось присвоить реквизит «Заблокирован» из-за одноимённого
метода COM. Создание контакта работает. Для фикстур присваивание исключено,
доставку предотвращают отключённый бот без токена и нулевые идентификаторы.
Производственный код ради теста не менялся.

После обновления также повторена проверка существующего тестового регистратора
только с базовой ролью МАКС, без Полных прав и без привилегированного режима:
служебные таблицы рассылок читаются, три параметра сеанса доступны,
запись существующей карточки клиента успешна и отменена транзакцией.
Боты, контакты и история ожидаемо недоступны. Сам тестовый пользователь не изменён.

## Что ещё не принято

- Сквозной диалог MAX → VDS → 1С и обратно с отдельным тестовым ботом.
- Динамические кнопки выбора отделения непосредственно в MAX.
- Выбор и доставка файла из интерфейса Единого чата, отказ от входящего файла.
- Интерфейс и серверные команды под всеми фактическими профилями клиентской КОРП.
- Запись заявки обычным пользователем при активных рассылках и работа реальной очереди.
- Пользовательские алгоритмы шаблонов.

Computer Use недоступен: native pipe os error 2 после повтора и сброса.
Это не мешает описанному запуску фиксированной EPF, но визуальная приёмка не выполнена.
Задачи не закрывать и не считать рабочую базу обновлённой на основании этого протокола.
